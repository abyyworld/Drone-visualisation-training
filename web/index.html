Analysis engine

The on-device model is free, private and instant, but only finds the defect classes it was trained on. A vision model called through an API has no fixed class list and will describe damage the detector was never taught, at the cost of sending each image to that provider and paying per image. Its boxes are approximate rather than pixel-tight.

A clip is sampled, then blurred and near-identical views are dropped, so only distinct in-focus frames are analysed. More frames means better coverage and, on an API engine, a proportionally larger bill.

With an API engine selected, each image is sent to the provider you chose and is no longer processed only on your device. The key is kept in this tab and is never saved to disk or sent anywhere else, but a key pasted into a browser is visible to anyone using this machine. For shared or automated use, run tools/vlm_inspect.py instead.

What this does

Upload photographs or a video clip. A clip is sampled and reduced to the distinct, in-focus frames worth looking at, then every image is checked for what it shows. Turbine blades, solar panels, crowds and wildfires are analysed; anything else is refused rather than guessed at. Findings are scored into a severity band and rolled up into an inspection verdict you can export as JSON or print as a PDF report.

Two engines. The on-device model runs in this browser, costs nothing, needs no connection once loaded, and never transmits an image - but it only finds the defect classes it was trained on. A provider API has no fixed class list and will describe damage the trained model was never taught, at the cost of sending each image to that provider and paying per image. Its boxes are approximate. Wind turbine blades

Detects corrosion, cracks and surface peeling. There is no “healthy” class by design - an image with no detections is the healthy result.

Solar panels RGB only

Detects soiling, bird droppings, cracks, discoloration, vegetation and missing modules.

Cannot detect hotspots, cell defects, bypass-diode failure or offline modules. Those are electrical faults visible only in thermal infrared, and no visible-light model can find them - including this one.

Wildfire one frame, one angle

Marks flame and the fire front, smoke and its direction, spot fires, people, vehicles, structures in the path, access and escape routes, water sources and the fuel and terrain that change how it runs.

It will not describe a scene as safe, clear, contained or empty of people, and neither should anyone reading it. Fire behind a smoke column, inside a treeline or under canopy does not appear from above, and a person the camera cannot resolve is the normal case rather than a rare one. A result with nothing in it describes the frame, not the ground.

Crowds regions, not people

Marks dense packing, choke points, counterflow, pressure against barriers, blocked exits, climbing and a person on the ground.

It marks regions, never individuals, and it never puts a number on how many people are present. At event density a person is a few pixels across and overlaps their neighbours, so boxing them one by one is not possible and a figure would be read as a measurement this image cannot support. An empty result describes one frame at one moment, and a crowd changes faster than that.

With the on-device engine, inference runs locally with ONNX Runtime Web and images are never transmitted. With a provider API selected, each image is uploaded to that provider and is subject to their terms and retention policy. Either way the results are a screening aid, not a certified structural assessment - confirm findings before acting on them.
